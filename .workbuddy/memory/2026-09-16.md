## 商户端开发计划（新产出）

产出文档：`商户端开发计划.md`（项目根目录）

**背景**：用户提出系统只有管理员端和用户端，缺商户端，要一份计划。

**调研结论（静态核对代码，未做动态验证）**：
- 全仓库 grep `merchant|商户|店铺|seller` 零命中 → 商户端确为从零新增。
- 角色只有两个：ADMIN（`admin` 表 + `/admin/login` + `ADMIN_TOKEN_SECRET`）、USER（`user` 表 + `/login`）。
  身份解析存在**三套并存**：`JwtInterceptor.java:84-95`（管理密钥验签）、`:104-112`（用户密码当密钥）、
  `TokenUtils.getCurrentUser()`（`:107` 只 `JWT.decode` 不验签）。
- **关键洞察**：`goods.admin_id` 是唯一「商品归属」字段（`GoodsServiceImpl.java:41,92`），
  8 条种子商品归属全是 admin_id=1 → **当前 admin 表实际扮演「唯一大商户」**，
  商户端本质 = 把商品所有权从 admin 剥离。
- 订单是单商户模型：`orders` 无 merchant_id，`order_item` 无商户维度，
  `OrdersServiceImpl.settle():90-106` 一次结算生成 1 单 + N 明细。

**计划中给出的三个核心决策（推荐项）**：
- D1 商户身份 → 新建 `merchant` 表 + 独立登录（与 `admin` 对称），**不**复用 user 表加 role
- D2 商品归属 → 新增 `goods.merchant_id`，`admin_id` 降级为「录入人」
- D3 跨商户订单 → **按 merchant_id 拆单**（`orders` 加 `merchant_id` + `parent_no` 批次号），
  而非「一张订单 + 明细挂商户」——后者无法表达订单主状态（A 发货 B 未发货时 state 无解）

**分五阶段**：Phase 0 前置治理（统一身份层，阻塞项）→ Phase 1 数据模型迁移 SQL →
Phase 2 后端四件套 → Phase 3 前端（复用 `Manager.vue` / `manager/Goods.vue` / `manager/Orders.vue`）→
Phase 4 入驻审核与资金台账（本期建议不做）。
