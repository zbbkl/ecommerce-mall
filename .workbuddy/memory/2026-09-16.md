## 商户端开发计划（新产出）

产出文档：`商户端开发计划.md`（项目根目录）

**背景**：用户提出系统只有管理员端和用户端，缺商户端，要一份计划。

**调研结论（静态核对代码，未做动态验证）**：
- 全仓库 grep `merchant|商户|店铺|seller` 零命中 → 商户端确为从零新增。
- 角色只有两个：ADMIN（`admin` 表 + `/admin/login` + `ADMIN_TOKEN_SECRET`）、USER（`user` 表 + `/login`）。
  身份解析存在**三套并存**：`JwtInterceptor.java:84-95`（管理密钥验签）、`:104-112`（用户密码当密钥）、
  `TokenUtils.getCurrentUser()`（`:107` 只 `JWT.decode` 不验签）。
- **关键洞察**：`goods.admin_id` 是唯一「商品归属」字段（`GoodsServiceImpl.java:41,92`），
  8 条种子商品归属全是 admin_id=1 → **当前 admin 表实际扮演「唯一大商户」**，
  商户端本质 = 把商品所有权从 admin 剥离。
- 订单是单商户模型：`orders` 无 merchant_id，`order_item` 无商户维度，
  `OrdersServiceImpl.settle():90-106` 一次结算生成 1 单 + N 明细。

**计划中给出的三个核心决策（推荐项）**：
- D1 商户身份 → 新建 `merchant` 表 + 独立登录（与 `admin` 对称），**不**复用 user 表加 role
- D2 商品归属 → 新增 `goods.merchant_id`，`admin_id` 降级为「录入人」
- D3 跨商户订单 → **按 merchant_id 拆单**（`orders` 加 `merchant_id` + `parent_no` 批次号），
  而非「一张订单 + 明细挂商户」——后者无法表达订单主状态（A 发货 B 未发货时 state 无解）

**分五阶段**：Phase 0 前置治理（统一身份层，阻塞项）→ Phase 1 数据模型迁移 SQL →
Phase 2 后端四件套 → Phase 3 前端（复用 `Manager.vue` / `manager/Goods.vue` / `manager/Orders.vue`）→
Phase 4 入驻审核与资金台账（本期建议不做）。

**注意**：`待修复与待办.md` 里的 P0-1（放行名单全放开，`InterceptorConfig.java:18-19` 至今仍是全放行原文）
与 Phase 0 高度重合，建议合并做，别做两遍。文档末尾附了两份待办的衔接表。

**当前状态**：计划已出，等用户确认 D1/D2/D3 三个决策后再动代码。

## 商户端改造执行（用户回复「开始执行计划」后按推荐方案落地）

### 代码变更清单

**Phase 0（统一身份层）**
- `application.yml`：新增 `jwt.secret`（支持 JWT_SECRET 环境变量覆盖）+ `jwt.expire-hours`
- `TokenUtils.java` 重写：单一密钥 `createToken(id, role)`；`getCurrentId/getCurrentRole/getCurrentUser/getCurrentAdmin/getCurrentMerchant` 全部从拦截器写入的 request attribute 读取，不再 decode token；新增 `getSecret()`
- `JwtInterceptor.java` 重写：全局密钥验签 → 角色表存在性校验 → 路径级角色控制（/admin/**→ADMIN、/merchant/**→MERCHANT、商品/分类/轮播写操作→ADMIN）→ 写入 attribute
- `InterceptorConfig.java`：放行收敛为 6 个登录/注册/密码入口；改 `implements WebMvcConfigurer`
- `GoodsController` 读接口、`TypeController.selectAll`、`CarouselController.selectAll` 加 `@AuthAccess`（保住前台匿名浏览）
- `WebController.register` 强制 role=USER

**Phase 1（SQL）**
- 新增 `sql/migration_merchant.sql`（存量库 ALTER + 种子商户回填，information_schema 幂等判断）
- `sql/code_scaffold.sql` 同步全量更新（新库直接可用）

**Phase 2（后端商户模块）**
- 新文件：`Merchant` 实体、`MerchantMapper`、`IMerchantService/Impl`（登录/入驻/资料/改密/平台分页/审核）、`IMerchantGoodsService/Impl`（归属强制=登录态，越权 403）、`IMerchantOrderService/Impl`（订单分页/详情/发货 ship/经营概览 stats）、`OrderState` 状态字典常量、四个 Controller（/merchant、/merchant/goods、/merchant/orders、/admin/merchant）
- `OrdersServiceImpl` 重写：settle 按 merchant_id **拆单**（LinkedHashMap 分组，同批次共用 parent_no）→ 返回批次号；pay(id) 安全版；payBatch(parentNo) 批量支付；cancel 回补库存（restoreStore 原子 SQL）；selectPage 角色隔离 + 判空（修 NPE 绕过）
- `OrdersController`：settle 返回 parentNo；新增 /orders/payBatch、/orders/cancel；/orders/update 限 ADMIN；pay 接收 {id}（Map 解析，兼容 Number/String）
- `GoodsServiceImpl.save`：管理员代录商品归属自营商户 merchantId=1；列表填充 merchantName
- `GoodsMapper`：新增 `restoreStore`（store+nums, sales-nums, 带 sales>=nums 防负）

**Phase 3（前端）**
- 新页面：`Merchant.vue` 外壳 + `merchant/{Home,Goods,Orders,Shop,Person}.vue`；管理端 `manager/Merchant.vue`（入驻审核：通过/驳回(带原因)/停用/恢复）
- `router/index.js`：/merchant 分组 + **角色守卫重写**（原来不校验角色，任意角色可进后台）
- `Login.vue` 加「商户」选项三分发；`Register.vue` 加「商户入驻」（shopName + /merchant/register，待审核提示）
- `Manager.vue` 加「商户管理→入驻审核」菜单（仅 ADMIN）
- `front/Orders.vue`：新状态筛选/标签、商户列、cancel 走 POST /orders/cancel、合并支付（同 parentNo）、收货人列改 user.name（修 userName 空白 bug）
- `front/GoodsDetail.vue`：立即购买改走 /orders/settle（金额服务端算）
- `manager/Goods.vue`：添加人列 → merchantName||adminName
